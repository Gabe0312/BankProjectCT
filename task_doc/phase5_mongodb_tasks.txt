=======================================================
DECISION MAKING NOTES
=======================================================

1. IDs: int -> str (ObjectId)
   MongoDB auto-generates _id as ObjectId. Represented as str in Python.
   Ripples through every model, service, and controller.

2. Async everywhere
   Motor is fully async — every DB call must be awaited.
   Repositories, services, and route handlers all become async def.
   FastAPI handles this natively.

3. Model split: request/response vs. DB document shape
   Request models stay as Pydantic BaseModel.
   PyObjectId helper added to serialize MongoDB _id -> str for responses.

4. Transactions: embedded in account document
   Transactions are stored as an embedded array inside the account document.
   transaction_repository uses MongoDB $push operator, not a separate collection.
   Correct for this use case — transactions always accessed via account context.

5. Audit log: separate MongoDB collection (NOT embedded)
   Audit records must be queryable across all accounts and customers for
   compliance purposes. Embedding inside account documents would make
   cross-account queries impossible. Separate collection is the right call.
   Every deposit, withdrawal, and transfer writes one audit record.

6. Transfer: service-layer operation
   Transfer is a two-account operation (debit one, credit another).
   Lives in account_service.py. Both account updates + audit write happen
   together. MongoDB does not enforce multi-document transactions on M0,
   so order is: debit -> credit -> audit. Failure after debit is logged in audit.

7. getPremiumAccounts(threshold)
   MongoDB query: db.accounts.find({ balance: { $gte: threshold } })
   Exposed as GET /accounts/premium?threshold=X

8. store.py stays until the end
   Deleted only after MongoDB is confirmed working (task 5.6.1).

9. db.py uses FastAPI lifespan context manager
   Modern approach — replaces deprecated on_event startup/shutdown hooks.

10. user.py merged into customer.py (Option 2)
    user.py and customer.py were the same entity with one extra field (phone).
    Decision: merge into customer.py, drop user.py, rename user_id -> customer_id
    throughout account.py and all future repositories/services/controllers.

11. account_controller.py has 3 known broken references (fixed in Step 5)
    - body.userId -> body.customerId
    - account_id: int -> account_id: str (all 4 route handlers)
    - sync def -> async def (all route handlers)
