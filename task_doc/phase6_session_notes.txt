POST-PHASE 6 FIXES — Friendly Reference Numbers & Bug Fixes
-----------------------------------------------------

FRIENDLY REFERENCE NUMBERS
- Replaced all raw MongoDB ObjectId hex strings in the UI with
  human-readable reference numbers across the entire stack.
- Four number types introduced:
    CUST-XXXXXX  — customers
    ACC-XXXXXX   — accounts
    AUD-XXXXXX   — audit records
    TXN-XXXXXX   — transactions (embedded in account documents)
- Generation: random 6-digit suffix via _generate_*_number() helpers
  added to each service (customer_service, account_service,
  audit_service). Numbers stored on the document at creation time.
- Fallback pattern used throughout frontend:
    friendly_number || raw_id_slice
  ensures UI never breaks for older records missing the new fields.
- Migration scripts written and run for all existing data, then deleted:
    migrate_reference_numbers.py       (customers + accounts)
    migrate_audit_reference_numbers.py (audit records)
    migrate_user_customer_numbers.py   (user_auth documents)
    migrate_account_customer_numbers.py(account customer_number field)
    migrate_audit_numbers.py           (AUD- numbers on audit records)
    migrate_txn_numbers.py             (TXN- numbers on embedded txns)

ACCESS DENIED BUG FIX — Transaction History / Deposit / Withdraw / Transfer
- Root cause: DepositPage, WithdrawPage, TransferPage, and
  TransactionHistoryPage were calling GET /api/accounts/{id} to
  fetch account_number. That route is require_admin — customers
  received 403 Access Denied.
- Fix: account_number is now passed via React Router state from
  CustomerDashboard when navigating to any action page.
  No extra API call needed.
- CustomerDashboard.jsx: handleAction now passes accountNumber as
  third argument and includes it in navigate() state.
- AccountCard.jsx: all four onAction calls pass account.account_number
  as third argument.
- DepositPage, WithdrawPage, TransferPage, TransactionHistoryPage:
  all now use useLocation() to read state.accountNumber.
  Fallback to accountId.slice(-6) if navigated to directly.
  TransactionHistoryPage reverted to single transactions fetch
  (removed the broken Promise.all that called the admin route).
  TransactionHistoryPage CSV export filename uses accountNumber.
- WithdrawPage: was missing useEffect import — caused blank page,
  now fixed.
